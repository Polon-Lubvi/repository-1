# TestQuest — автотесты «Калькулятора смет»

Комплект тест-кейсов и автотестов для раздела
**TestQuest → Продажи → «Калькулятор смет»** (ПО «Бублики»),
стенд **https://testquest.pryaniky.com/**.

* `TESTCASES.md` — 14 тест-кейсов (Название · Предусловие · Шаги · ОР) + список найденных дефектов.
* `tests/` — автотесты, покрывающие все 14 кейсов (~160 проверок в 9 блоках).
* `run-tests.sh` / `run-tests.bat` — запуск «из коробки», без установки зависимостей.

Проверено в песочнице задания: `run-tests.sh` → `RESULT: PASSED`, exit code `0`
(рантайм — Node.js v20, прогон ~0.7 c).

---

## Как запустить

### Требования
Один из рантаймов (берётся первый найденный), **без сторонних пакетов**:

| Рантайм | Чем выполняется | Что использует |
|---------|-----------------|----------------|
| **Node.js 18+** (приоритет) | `node tests/run` | встроенный `fetch`, стандартная библиотека |
| **Python 3.8+** | `python tests/run.py` | `urllib`, `zipfile`, `re`, `base64` |

Нужен доступ в интернет к `https://testquest.pryaniky.com` (тесты обращаются
к живому стенду).

### Linux / macOS
```bash
BASE_URL=https://testquest.pryaniky.com ./run-tests.sh
```

### Windows
```bat
set BASE_URL=https://testquest.pryaniky.com
run-tests.bat
```

Если `BASE_URL` не задан — используется `https://testquest.pryaniky.com`.

### Напрямую, без скриптов
```bash
BASE_URL=https://testquest.pryaniky.com node   tests/run       # Node
BASE_URL=https://testquest.pryaniky.com python tests/run.py     # Python
```

> Файл `tests/run` намеренно без расширения `.js` — песочница задания запрещает
> в архиве исполняемые расширения (`.js`, `.mjs`, `.exe`, …). Node прекрасно
> исполняет его как CommonJS по явной команде `node tests/run`.

## Как устроены тесты

SPA калькулятора — полностью клиентская: вся логика в `*.js`, которые отдаёт
стенд. Тесты работают с **реально задеплоенным стендом** по `BASE_URL`:

1. **Числовая логика.** Движок ценообразования (`js/calc.js`) портирован
   (`tests/run` для Node, `tests/lib/tq.py` для Python) и сверен 1:1 с живым
   калькулятором на десятках сценариев. Константы (цены, дивизоры, скидки,
   коэффициенты модулей, пресеты внедрения, ставка T&M, менеджеры)
   **вычитываются из `js/data.js` стенда** при каждом прогоне — если цену на
   стенде поменяют, тест это заметит.
2. **Контракт разметки и поведение.** Проверяется `index.html` и логика в
   `js/app.js`, `js/exportEstimate.js`, `js/formValidation.js`, `js/invoice.js`,
   `js/act.js`, `js/contract.js`, `js/nav.js`, `js/modulesPicker.js`: наличие
   полей, вкладок, кнопок; формула агрегатора «ИТОГО»; правила валидации;
   маска имени файла выгрузки.
3. **Выгрузка Excel.** Шаблон КП (`js/kp-template-base64.js`) декодируется из
   base64 и проверяется как валидный OOXML-контейнер (сигнатура ZIP,
   `[Content_Types].xml`, `xl/workbook.xml`, листы, медиа); проверяется
   покраска подставленных значений (`ARGB FF00B050`).

Такой подход даёт стабильный прогон меньше чем за секунду, без установки
браузеров и без флейков, оставаясь привязанным к живому стенду.

### Структура
```
run-tests.sh / run-tests.bat     запуск (Node → Python)
tests/run                        весь набор для Node (без расширения, CommonJS)
tests/run.py                     тот же набор для Python
tests/lib/tq.py                  Python: загрузка стенда + порт движка + парсер data.js
tests/lib/harness.py             Python: мини-ассерты
tests/test_*.py                  Python: блоки по кейсам (TC-01…TC-14)
```

## Известные дефекты
Кратко (подробно — в конце `TESTCASES.md`):

* **BUG-1** — выгрузка Excel не валидирует мета-поля КП (компания, число лицензий, срок): КП формируется с пустыми значениями и «0 месяцев».
* **BUG-2** — для тарифа «Коробка» поле «Срок, мес» не влияет на цену лицензий (только на число оплаченных лет тех.поддержки), но выглядит редактируемым.
* **BUG-3** — «Коробка» не обнуляет смету при 0 лицензий / 0 месяцев (облако — обнуляет).
* **BUG-4** — поле «К-т роста г/г» не валидируется; ввод `0` или пустое значение молча обнуляет смету по лицензиям.

Тесты `TC-12` содержат «канарейки» на BUG-1 и BUG-4: если поведение исправят,
проверки станут красными — сигнал обновить кейсы.
