# ScoutQA — исследовательское тестирование

Удалённый агент сам обходит сайт по заданной цели и возвращает список найденных дефектов.

> **Этот файл исправлен.** Оригинал из github/awesome-copilot описывал команды, которых
> в CLI нет. Ниже — набор, сверенный с `@scoutqa/cli` 0.10.4-alpha.1 напрямую через
> `--help` 18 сентября 2026. Перед использованием стоит пересверить: версия альфовая,
> команды могут измениться.

---

## Предварительные условия

| Условие | Состояние на момент сверки |
|---------|---------------------------|
| CLI установлен | Да, `@scoutqa/cli` 0.10.4-alpha.1 |
| Авторизация | **Нет.** Без неё ни одна команда не отработает |
| Куда уходят данные | `https://app.scoutqa.ai` — тест целиком идёт на их инфраструктуре |

Авторизация — дело пользователя, не агента:

```bash
scoutqa auth login
```

Либо переменная окружения `SCOUT_API_KEY`. Проверить текущее состояние:

```bash
scoutqa auth status
```

**Пароли, ключи и токены агент не вводит и не хранит.** Если авторизации нет — сказать
об этом и остановиться, а не пытаться обойти.

Конфиг лежит в `%APPDATA%\scoutqa-nodejs\Config\config.json`.

## Реальный набор команд

Проверено через `scoutqa --help` и `scoutqa <cmd> --help`:

| Команда | Назначение |
|---------|-----------|
| `scoutqa create-execution` | Запустить тест |
| `scoutqa send-message` | Дослать агенту сообщение в идущий тест |
| `scoutqa list-executions` | Список своих прогонов |
| `scoutqa complete-execution` | Завершить прогон и освободить ресурсы |
| `scoutqa auth` | `status`, `login`, `logout`, `set-api-key`, `create-api-key` |

Флаги `create-execution`:

```
--url <url>               адрес для тестирования
--prompt <prompt>         инструкция на естественном языке
--project-id <projectId>  привязка к проекту
-v, --verbose             показывать все вызовы инструментов
```

### Команд, которых НЕ существует

Оригинальный скилл описывал их как рабочие. Не вызывать — вернётся ошибка:

- `scoutqa --url ... --prompt ...` — **верхнеуровневой формы нет**, только `create-execution`
- `scoutqa list-issues --execution-id ...`
- `scoutqa issue-verify --issue-id ...`
- `scoutqa get-execution --execution-id ...`

Списка дефектов через CLI получить нельзя. Результаты смотрятся по ссылке
`app.scoutqa.ai/t/<id>`, которую печатает сам прогон.

## Как запускать

```bash
scoutqa create-execution --url "<адрес>" --prompt "<что исследовать>"
```

Прогон долгий. Запускать **в фоне** — параметром `run_in_background` у Bash-инструмента.

> **Не использовать приём из оригинала.** Там предписано ставить таймаут Bash в 5000 мс
> и утверждается, что процесс после таймаута продолжит работать в фоне. Это неверно:
> таймаут завершает команду, а фоновый запуск — отдельный флаг. Следование оригиналу
> обрывало бы тест на пятой секунде.

В первых секундах вывода появляются идентификатор прогона и ссылка вида
`https://app.scoutqa.ai/t/019b831d-xxx`. Их надо сразу отдать пользователю — дальше он
следит за ходом в браузере сам.

Если агент застрял или просит уточнений:

```bash
scoutqa send-message --execution-id <id> --prompt "<уточнение>"
```

## Как писать промпт

Описывать **что исследовать**, а не **какие шаги делать** — агент сам сообразит маршрут.

```bash
scoutqa create-execution --url "https://example.com" --prompt "
Исследуй регистрацию. Проверь валидацию полей на граничных значениях,
обработку ошибок и доступность форм.
"
```

Работающие формулировки целей:

- Аутентификация: вход, выход, восстановление пароля, поведение сессии
- Каталог и поиск: фильтры, сортировка, пустая выдача, длинные запросы
- Корзина и оплата: пересчёт цен, сохранение корзины, способы оплаты
- Личный кабинет: вкладки, сохранение настроек, история операций

**Ничего необратимого.** Не задавать целей, ведущих к реальной оплате, удалению данных
или рассылке писем живым людям, если пользователь не подтвердил это отдельно.

## Что отдавать пользователю

Сразу после запуска:

```
Прогон запущен.
ID: 019b831d-xxx
Смотреть вживую: https://app.scoutqa.ai/t/019b831d-xxx
```

По завершении список дефектов через CLI не достаётся — пересказать то, что напечатал
сам прогон, и дать ссылку на полный отчёт со скриншотами.

## Когда этот скилл, а когда qa-web-sweep

| Нужно | Скилл |
|-------|-------|
| Механические проверки: контраст, битые ссылки, вёрстка, доступность | `qa-web-sweep` — локально, бесплатно, без авторизации |
| Сценарный обход с суждением: пройти регистрацию, найти неочевидное | `scoutqa-test` — этот |
| Тест-план, тест-кейсы, баг-репорты на бумаге | `qa-test-planner` |

Если задача покрывается `qa-web-sweep` — брать его: он не требует авторизации
и не отправляет адрес наружу.
