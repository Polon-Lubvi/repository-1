# Тест-план: Unyson — приёмочное тестирование

**Версия:** 1.0
**Дата:** 2026-09-18
**Основание:** ТЗ для тестировщиков (Unyson — 3 тестировщика × 10 часов), Чек-лист тестирования Unyson
**Бюджет:** 30 человеко-часов (3 × 10 ч)

---

## 1. Резюме

Приёмочная проверка сервиса Unyson с позиции обычного пользователя. Фокус — корректность списаний с баланса, работа подписки, каталог нейросетей, вёрстка и удобство использования. Объём разделён между тремя тестировщиками так, чтобы каждая категория нейросетей была покрыта минимум одним человеком, а баланс и списание проверялись отдельно на каждом тарифе (цена на них разная).

**Ключевой риск:** четыре пункта чек-листа физически не укладываются в 10-часовое окно (см. §8 и §9). Без решения по ним приёмка будет неполной.

---

## 2. Область тестирования

### В scope

| Область | Тестировщик | Часы |
|---------|-------------|------|
| Регистрация, вход, пробные генерации без аккаунта | Т1 | 1 |
| Баланс и списание — Базовый / Стандарт / ПРО | Т1 / Т2 / Т3 | 1,5 / 1 / 1 |
| Нейросети: изображения, аудио | Т1 | 4 |
| Нейросети: видео, текст/чат | Т2 | 4 |
| Нейросети: 3D, утилиты, выборочная версия | Т3 | 4 |
| Подписка: оформление, заморозка, отмена | Т2 | 2 |
| Смена тарифа, автопополнение, способы оплаты | Т3 | 1 |
| Личный кабинет — все вкладки | Т2 | 1,5 |
| Доступы, проекты, закреплённые нейросети | Т3 | 1,5 |
| Юридические страницы и cookie-баннер | Т1 | 0,5 |
| Обработка ошибок (тексты, 404, модалки) | Т3 | 1 |
| Вёрстка: мобильная, темы, Chrome/Firefox/Safari | Т1 / Т2 / Т3 | 2 / 1 / 1 |
| Оформление багов | Т1 / Т2 / Т3 | 1 / 0,5 / 0,5 |

Бюджет сходится: 10 ч на каждого тестировщика.

### Вне scope

- Нагрузочное и стресс-тестирование
- Тестирование безопасности (SQL-инъекции, XSS, обход авторизации)
- Тестирование API в обход интерфейса
- Автоматизация тестов
- Качество самих результатов генерации как таковое (оцениваем только факт получения результата и соответствие описанию, не художественную ценность)
- Интеграции со сторонними сервисами глубже точки оплаты

Исключения осознанные, но безопасность стоит вынести в отдельную работу: сервис принимает платежи и хранит платёжные данные.

## 3. Стратегия

**Метод:** ручное тестирование, чёрный ящик, от лица обычного пользователя.

**Виды проверок:**
- Функциональное — позитивные и негативные сценарии
- Исследовательское — в рамках своего блока, сверх чек-листа
- Кроссбраузерное и адаптивное — Chrome, Firefox, Safari, мобильная версия
- Проверка граничных значений — на степперах, лимитах, суммах

**Что проверяется всегда, в любом блоке (ТЗ §3):**

1. Цена на кнопке до клика совпадает с суммой фактического списания
2. При отказе модерации или обрыве соединения баланс не уменьшается
3. Ничего не обрезано, не съехало, нет битых иконок — ни в какой теме
4. Интерфейс понятен без подсказок
5. Каждая страница открывается в тёмной и светлой теме без потери читаемости

> **Важно:** пункты 3–5 в текущем чек-листе закреплены только за Т1 (строки 14–15), а Т1 проверяет лишь свои страницы. Личный кабинет, 3D, доступы и страницы ошибок остаются без проверки тем. См. §9, замечание 4.

## 4. Тестовое окружение

| Параметр | Значение |
|----------|----------|
| Стенд | Уточнить: продакшн или прод-подобный (влияет на риск R3) |
| Браузеры | Chrome (Т3), Firefox (Т2), Safari (Т2), мобильный браузер (Т1, Т3) |
| Устройства | Десктоп + реальный смартфон (не только режим эмуляции DevTools) |
| Темы | Тёмная и светлая — обе обязательны |
| ОС | Для Safari требуется macOS или iOS — см. риск R1 |

## 5. Тестовые данные и аккаунты

| Тестировщик | Тариф | Что нужно подготовить до старта |
|-------------|-------|--------------------------------|
| Т1 | Без подписки (Базовый) | Аккаунт, баланс под весь блок генераций; чистый браузер для cookie-баннера и пробных генераций без аккаунта |
| Т2 | Стандарт | Аккаунт, баланс, оплаченная подписка помесячно **и** годовая |
| Т3 | ПРО | Аккаунт, баланс, привязанная карта для автопополнения, реквизиты юрлица для счёта с УПД |

Дополнительно:

- Учётки Яндекс и VK для проверки входа через соцсети (Т1)
- Второй пользователь для проверки приглашения с лимитом в сонах (Т3)
- Файлы для вложений в чат: документ, изображение, голосовое (Т2)
- Исходное фото для оживления и для 3D по фото (Т2, Т3)

## 6. Критерии входа

- [ ] Стенд развёрнут и доступен всем трём тестировщикам
- [ ] Три аккаунта созданы, тарифы активированы, балансы пополнены
- [ ] Реквизиты юрлица получены (иначе Т3 п.4 снимается — см. §9)
- [ ] Принято решение по заморозке и отмене подписки (см. §9, замечание 1)
- [ ] Доступ к устройству с Safari подтверждён (см. R1)
- [ ] Таблица багов заведена и доступна на запись всем троим

---

## 7. Критерии выхода

### Блокирует релиз (из ТЗ §5)

- Любая ошибка некорректного списания — списалось больше, меньше или дважды
- Генерация оплачена, результат не получен, баланс не возвращён
- Невозможность зарегистрироваться или оплатить основным способом
- Полная неработоспособность любой из проверяемых категорий нейросетей

### Не блокирует

Визуальные огрехи, шероховатости в формулировках — фиксируются как задачи на доработку.

### Формальные критерии приёмки

- [ ] Все пункты чек-листа со статусом, отличным от «Не выполнен»
- [ ] Ни одного открытого блокирующего дефекта из списка выше
- [ ] Каждая из шести категорий нейросетей проверена хотя бы одним тестировщиком
- [ ] Списание проверено на всех трёх тарифах
- [ ] Пункты, признанные непроверяемыми в окне 10 ч, зафиксированы письменно с причиной

## 8. Оценка рисков

| ID | Риск | Вероятность | Влияние | Митигация |
|----|------|-------------|---------|-----------|
| R1 | Safari недоступен — не запускается на Windows | Высокая | Среднее | Заранее выдать Mac/iPhone или доступ к BrowserStack; иначе снять пункт и зафиксировать непокрытие |
| R2 | Заморозка на 30 дней и бонус 14 дней не проверяются за 10 ч | **Высокая** | **Высокое** | Бэкенд-сдвиг даты или тестовый флаг ускорения; иначе проверять только момент инициации |
| R3 | Тестирование платежей на продакшне — реальные списания | Средняя | Высокое | Прод-подобный стенд с тестовым эквайрингом; иначе согласовать бюджет и лимит карты |
| R4 | Автопополнение требует реально уронить баланс ниже порога | Средняя | Среднее | Выставить порог заведомо высоким, чтобы триггер сработал быстро |
| R5 | Оплата по счёту с УПД идёт банковскими днями | Высокая | Среднее | Проверять только формирование счёта; статус оплаты — вне окна |
| R6 | 4 ч на категорию нейросетей при 2–3 версиях каждая — оценка оптимистична | Средняя | Среднее | Приоритизировать флагманскую версию; лёгкую — если останется время |
| R7 | Дубль проверки фона и апскейла у Т1 и Т3 съедает время | Средняя | Низкое | Развести явно (см. §9, замечание 3) |
| R8 | Баг-репорты без скриншотов невоспроизводимы | Средняя | Среднее | Запись экрана включена постоянно, а не по факту находки |

## 9. Замечания к исходным документам

Найдено при сверке ТЗ с чек-листом. Требуют решения **до** старта.

**1. Заморозка и отмена подписки не укладываются в окно.**
Т2 п.2 — «Заморозка подписки на 30 дней → оплаченные дни сохраняются». Т2 п.3 — флоу отмены с бонусом 14 дней. Проверить сохранность дней через 30 дней за 10 часов невозможно.
*Решение:* либо тестовый механизм сдвига времени, либо переформулировать ожидаемый результат на «заморозка инициируется, счётчик оплаченных дней на момент заморозки корректен».

**2. Т2 п.2 и п.3 конфликтуют по состоянию аккаунта.**
П.3 начинается с шага «заморозка», но аккаунт уже заморожен в п.2. На одном аккаунте последовательно эти два пункта чисто не проходятся.
*Решение:* второй аккаунт на Стандарте либо явный порядок с разморозкой между пунктами.

**3. Дублирование между Т1 и Т3 — вопреки ТЗ.**
ТЗ заявляет «повторов между тестировщиками нет, кроме баланса и списания». Фактически Т1 п.9 («редактирование фото, апскейл, удаление фона») и Т3 п.6 («удаление фона и увеличение разрешения отдельными карточками») пересекаются.
*Решение:* если это намеренная проверка одной функции в двух точках входа — записать это в ожидаемый результат явно. Если нет — освободить час у Т1.

**4. Проверка тем покрывает не весь сервис.**
ТЗ §3 требует проверять обе темы на каждой странице. В чек-листе это только строка Т1 п.15, а Т1 не заходит в личный кабинет Т2, в доступы Т3 и на страницы ошибок.
*Решение:* добавить строку «обе темы на своих страницах» каждому тестировщику.

**5. Оплата по счёту с УПД требует реквизитов юрлица.**
Т3 п.4. Если реквизитов нет — пункт невыполним. Вынесено в критерии входа.

**6. Двойной клик по «Сгенерировать» (Т1 п.7) — фактически блокирующая проверка.**
Двойное списание прямо указано в ТЗ §5 как блокер релиза, но в чек-листе пункт идёт рядовой строкой внутри полуторачасового блока.
*Решение:* поднять приоритет до P0 и выполнять первым в блоке баланса.

## 10. График

| Этап | Длительность | Ответственный |
|------|--------------|---------------|
| Подготовка стенда, аккаунтов, реквизитов | до старта | Заказчик |
| Решение по замечаниям §9 | до старта | Заказчик + QA-лид |
| Блок 1: регистрация / подписка / оплата | 1–2 ч | Т1, Т2, Т3 параллельно |
| Блок 2: баланс и списание | 1–1,5 ч | Все трое |
| Блок 3: нейросети | 4 ч | Все трое |
| Блок 4: кабинет / доступы / ошибки / юр. страницы | 0,5–1,5 ч | По распределению |
| Блок 5: вёрстка | 1–2 ч | По распределению |
| Оформление багов | 0,5–1 ч | Все трое |

Блок баланса выполняется **до** блока нейросетей: он дешевле по времени и вскрывает блокеры раньше.

## 11. Артефакты

- Настоящий тест-план
- Заполненный чек-лист со статусами (лист «Чек-лист»)
- Таблица багов (лист «Баги»)
- Скриншоты и записи экрана по каждому дефекту
- Итоговый отчёт: покрытие, блокеры, рекомендация go / no-go
- Список пунктов, признанных непроверяемыми в окне, с причинами
