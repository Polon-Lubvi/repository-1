# Шаблон сайта центра ГБО

Готовый одностраничник для центра установки и обслуживания ГБО
(газобаллонного оборудования). Чистая статика — никакого npm и сборки,
файлы открываются как есть. Сделан на основе шаблона автосервиса
([Shablon_Avtoservice](../Shablon_Avtoservice)), который в свою очередь
сделан из сайта Auto Region 161 — текст, калькулятор и гарантии переписаны
под установку и настройку ГБО.

Главная мысль сайта: **гарантию дилера на двигатель сохраняем** — потому
что монтаж и настройка выполняются по регламенту, а не «на глаз». Второй
слой: экономию и срок окупаемости считаем до установки, а не после.

## Как посмотреть

```bash
cd ~/Desktop/ClodeCode/Sites_Projeckt/Shablon_CentrGBO/site && python3 -m http.server 8904
```

Дальше открыть http://localhost:8904 . Порт лучше каждый раз новый —
браузер жёстко кэширует старую версию.

## Как сделать вариант под конкретный центр

**Копировать папку целиком** (`Site_<название>`), править копию. Сам
шаблон остаётся чистым.

Дальше по файлам:

| Что меняем | Где |
|---|---|
| Название, телефон, адрес, реквизиты, ссылки на Яндекс.Карты и Авито | `site/config.js` |
| Все тексты: заголовки, услуги, отзывы, вопросы, гарантия | `site/content.js` |
| Цвет и шрифт | `site/theme.css` |
| Заголовок вкладки и описание для поиска | `site/index.html` |

Цвет меняется **только** в `theme.css` и сразу всем блоком переменных
«Акцент», а не одной `--accent`.

## Фотографии

В шаблоне фотографий нет вообще — везде стоят плашки с подписью, какой
кадр туда нужен. Это удобно вдвойне: сайт можно показывать как есть, а
клиент по плашкам сразу понимает, что от него нужно прислать.

Чтобы поставить фото, в `content.js` у нужной плашки добавить `src`:

```js
{ src: 'img/boks.jpg', need: 'Монтажный бокс с подъёмниками', w: 1600, h: 1069 }
```

Файл положить в `site/img/`. Фото пережимать в JPEG примерно 1400–1600 px
по длинной стороне, качество 80 — иначе страница тормозит на телефоне.
Обрезать и «улучшать» фильтрами не надо, вёрстка подстраивается под кадр
сама.

## Чего нельзя делать

- Никаких `blur`, `backdrop-filter` и бесконечных анимаций — сайт должен
  летать на телефоне.
- `white-space: nowrap` на длинной строке ломает мобильную вёрстку: страница
  становится шире экрана и всё съезжает.
- В комментариях CSS не должно быть `*/` внутри текста — это молча обрывает
  комментарий и ломает следующую переменную.
- Блок мобильных правил в конце `blocks.css` должен оставаться последним.

## Что проверять перед отправкой клиенту

Телефон и десктоп, обе ширины. Пройти все три вкладки в блоке «что мы
делаем», раскрыть все вопросы, проверить кнопки WhatsApp и ссылку на
Яндекс.Карты.
